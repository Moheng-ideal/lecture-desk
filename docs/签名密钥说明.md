# 签名密钥说明与安全清单

> 更新：2026-11-27
> 重要性：**密钥泄露会导致他人可以签发冒充本应用的 APK**

---

## 一、密钥位置

| 文件 | 路径 | 用途 |
|---|---|---|
| 签名库 | `.sites-runtime/android-signing/lecture-desk.p12` | APK 签名证书（PKCS12） |
| 密码 | `.sites-runtime/android-signing/store.secret` | 签名库密码（明文，一行） |
| 旧密钥备份 | `.sites-runtime/android-signing/backup-20261127/` | 2026-11-27 之前的旧签名，仅作归档 |

打包脚本 `scripts/build-android.ps1` 会自动读取这两个文件；缺失时会**重新生成一套新签名**（务必避免，会导致覆盖升级失效）。

## 二、当前使用的密钥

| 项 | 值 |
|---|---|
| SHA-256（p12） | `881830A6C8D59BE5FC5F672516EFD01F…` |
| 来源 | 维护者提供（2026-11-27） |
| 是否与旧密钥一致 | **否**（旧密钥 `1F9F8029…`，已备份） |

> 用新密钥签出的 APK **无法覆盖安装**用旧密钥签的包；已装旧版的设备需要卸载重装（会丢失本机数据，提前导出问答录）。

## 三、上传 GitHub 前的安全清单

`git status` 前逐条确认：

- [ ] `.sites-runtime/` 被 `.gitignore` 忽略（含密钥目录）
- [ ] `release/` 被忽略（APK 产物）
- [ ] `.env` 被忽略（含局域网口令）
- [ ] 无散落的 `*.p12` / `store.secret` 在项目目录内
- [ ] `dist/`、`node_modules/` 未提交
- [ ] `v0.8.7-changes.zip` 等打包产物不含密钥（已验证）
- [ ] 提交前执行 `git status --short`，确认无 `android-signing`、`store.secret`、`.env`

### 快速自检命令

```powershell
cd D:\Dsh_project\lecture-desk
# 1) 应输出 true
git check-ignore -v .sites-runtime/android-signing/lecture-desk.p12
# 2) 应无输出
git status --short | Select-String -Pattern 'sites-runtime|store\.secret|\.p12|\.env$'
```

## 五、注意事项

1. **不要把密钥提交到任何 Git 仓库**（包括 fork、私有仓库）
2. 传给协作者时用加密渠道，不要直接发微信/邮件
3. 密钥丢失 = 无法再发布可覆盖升级的新版本，务必保留备份
4. 打包前确认 `.sites-runtime/android-signing/` 存在且是正确的那一套
5. `store.secret` 是明文密码，任何能读该文件的人都能签名
