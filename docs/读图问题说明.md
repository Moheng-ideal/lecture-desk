## 二、问题 1：上传服务网络不可达

### 现象

| 方向                                     | 结果                                    | 测试方    |
| -------------------------------------- | ------------------------------------- | ------ |
| 部署机 → `192.168.160.104:31010`          | ✅ 通（nc 测试 succeeded）                  | 火山引擎运维 |
| 校园网 10.1.x.x → `192.168.160.104:31010` | ❌ TCP 超时（curl 报 Connection timed out） | 应用开发方  |

### 原因

`192.168.160.104` 是**集群侧私有地址**（RFC1918 网段），校园网没有到该网段的路由，数据包被丢弃。

### 需要

请学校网络中心开通以下访问策略：

- **来源**：校园网 `10.1.0.0/16`（教学区终端）
- **目标**：`192.168.160.104`
- **端口**：TCP `31010`（上传）、`31011`（下载）
- **用途**：调用校内 NK-GeniOS 平台的 up-upload / up-download 服务，上传课件截图给 AI 智能体

> 说明：该地址由火山引擎运维提供（`kubectl get svc -A | grep up` 查询结果为 up-upload 的 NodePort），不是外部地址。

## 三、问题 2：API 传图返回"大模型接口调用出错"

### 现象

按官方文档把上传后的文件路径填入 `QueryExtends.Files` 调用返回业务错误：

```json
POST /api/proxy/api/v1/chat_query_v2
Header: Apikey: <智能体密钥>

{
  "AppConversationID": "<会话ID>",
  "UserID": "lecture-desk",
  "Query": "描述这张图片的内容。",
  "ResponseMode": "streaming",
  "QueryExtends": {
    "Files": [{
      "Name": "屏幕截图 2026-11-25 133125.png",
      "Path": "upload/full/4d/cf/b1f0265ec9f71217de737adf61c49442c13fc766c49b9c027cd12599dc3f",
      "Size": 300000,
      "Url": "upload/full/4d/cf/b1f0265ec9f71217de737adf61c49442c13fc766c49b9c027cd12599dc3f"
    }]
  }
}
```

**返回**：HTTP 200，流式内容为 **"大模型接口调用出错，请联系管理员"**

### 排查过程与验证记录

| 测试                                         | 结果                                                                                | 说明                               |
| ------------------------------------------ | --------------------------------------------------------------------------------- | -------------------------------- |
| 标准格式 `{Name, Path, Size, Url}` + 真实上传 Path | 返回"大模型接口调用出错"                                                                     | 请求被接受，卡在模型调用阶段                   |
| 错误格式 `{type:"image", image:{name, url}}`   | HTTP 400 `CheckUploadFilesConfig error: the format file content is not supported` | **证明文件格式校验确实生效**，标准 4 字段结构才是正确写法 |
| 两次不同时间上传的 Path（12:42、13:31）                | 均报同样错误                                                                            | 排除单次上传文件损坏                       |
| `Url` 填空 / 填路径 / 填完整 https 地址              | 空和无 Key 时返回 `[]`；填路径或 https 均报模型调用错误                                              | 排除单一字段取值问题                       |
| 同密钥纯文字对话                                   | 正常返回讲解内容                                                                          | 排除密钥、会话、网络层问题                    |
| 尝试把图片 base64 塞进 `Query` 文本                 | 智能体只能解析 PNG 文件头（尺寸、位深），明确表示"无法解码像素数据"                                             | 证明文本通道无法替代图片通道                   |

### 最可能的根因（按可能性排序）

1. **API 处理 `Files` 时读不到 OBS 文件**

   - 上传文件可能关联到网页会话，API 会话取不到
   - 或 `Url` 字段要求完整签名下载地址，当前传路径导致平台取文件失败

2. **多模态请求构造失败**

   - 网页端会把图片转成 `{type:"image", image:{...}}` 塞进模型输入
   - API 路径可能没有做这一步转换，直接调用模型时报错

3. **平台版本缺陷**

   - 网页端与 API 走两套代码，API 侧文件传入路径未经充分验证

### 关键区别（核心排查线索）

```
网页端调用树：
  input: [
    { type: "text",  text: "图里讲了什么" },
    { type: "image", image: { name: "屏幕截图 ...png",
                              url: "upload/full/4d/cf/..." } }
  ]
      ↑ 图片被转成多模态输入，模型可读

API 调用：
  QueryExtends.Files: [{ Name, Path, Size, Url }]
      ↑ 这是"附件列表"结构，平台需要自行转成上面的 image 输入
        转换这一步大概率失败
```

### 已排除的原因

| 假设           | 排除依据                                               |
| ------------ | -------------------------------------------------- |
| 模型不支持图片      | 网页端同一张图可正常识图（模型 `deepseek-v4-1-flash-260910` 支持视觉） |
| 密钥/权限问题      | 同一密钥文字对话正常                                         |
| Files 字段格式错误 | 格式被接受（错误格式会返回 400 参数校验错误）                          |
| 文件路径过期       | 刚上传的新文件同样报错                                        |

### 需要

请火山引擎售后协助确认：

1. API 的 `QueryExtends.Files` 与网页端上传图片，**平台内部处理路径是否一致**？是否会把 `Files` 转成模型的多模态输入？
2. `Files` 中 `Url` 字段应填 **完整下载 URL** 还是 **OBS 路径**？是否需要额外字段（如 `fileId`、`Key`、`contentType`）？
3. 能否提供 **API 传图的正确请求示例**（含 `QueryExtends.Files` 完整结构）？
4. 能否调取该次调用的后台日志？错误发生在"模型调用"阶段，日志中应有具体原因（读取文件失败 / 图片解码失败 / 多模态参数错误等）。

> **便于定位的补充信息**：问题复现时间约 2026-11-25 13:31–13:40，UserID 为 `lecture-desk`，使用智能体密钥对应"课件讲解师"应用。

## 五、技术参考

### 上传接口（来自官方《上传文件服务调用说明》）

- SDK：`hiagent-api==2.2.0`，`UpService`
- 接口：`POST /up?Action=UploadRaw&Version=2022-01-01`
- 鉴权：AK/SK 签名（火山引擎 SigV4）
- 必带请求头：`X-Content-Sha256`
- 参数：`Id`、`ContentType`、`Expire`（如 `3h`）、`Sha256`

### 签名要点（参考 hiagent-java-sdk PR #40 修复）

| 项             | 值                           |
| ------------- | --------------------------- |
| service       | `up`                        |
| SignedHeaders | `x-content-sha256;x-date`   |
| 是否签 host      | 否（网关改写 Host 仍可通过）           |
| canonical URI | 使用实际请求路径（如 `/up`），不要固定为 `/` |
| 请求体哈希         | 必须对**原始二进制**计算 SHA256       |

### 对话接口（带图片）

- `POST /api/proxy/api/v1/chat_query_v2`
- **带图片时仅支持 `ResponseMode: streaming`**，不支持 `blocking`
- 图片通过 `QueryExtends.Files` 传入
