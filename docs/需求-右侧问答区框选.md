# 需求：选文框选扩展到右侧问答区

> 整理时间：2026-11-26
> 状态：待方案确认
> 涉及平台：Web / Android WebView / 鸿蒙 ArkWeb（共用前端）

---

## 一、需求描述

当前「选文」只能框选左侧课本区，生成截图引用用于提问。希望也能**框选右侧问答区**（讲解师的回答），把选中的回答作为引用，支持继续追问（如"这段再展开讲讲"）。

---

## 二、现状（左侧选文机制）

| 环节 | 实现 |
|---|---|
| 工具栏 | `index.html` 第 47 行：`<button data-tool="select">选文</button>` |
| 选择层 | 左侧 `.ink` 画布（reader 的覆盖层），拖动时 `setBounds` 记录矩形 |
| 确认按钮 | `#use-selection`（「添加截图」），调用 `reader.quoteSelection()` |
| 截图 | `capturePage(page, bounds, '选文截图')` → 裁剪区域 → data URL |
| 引用 | `onQuote(reference)` → `state.references` → 显示为 chip → 随提问发送 |
| 服务端 | `chatInput()` 把 references 转成多模态 parts（图片 + 页码标签） |

**关键文件**：`src/reader.js`（`quoteSelection`/`capturePage`/`setBounds`）、`src/main.js`（`addExcerpt`/`displayExcerpts`）、`src/excerpts.js`（`isExcerptImage`/`currentReferences`）

---

## 三、技术约束

| 方式 | 可行性 | 原因 |
|---|---|---|
| 矩形框选 + 截图 | ❌ | 右侧是 DOM 文本，无浏览器原生区域截图 API；html2canvas 受 CSP `default-src 'self'` 限制且脆弱 |
| 矩形框选 + 文本提取 | ✅ | `document.caretRangeFromPoint` + `Range` 可把矩形起止点映射为文本范围 |
| 原生文字选择 + 引用按钮 | ✅ | 浏览器原生 selection，实现最简单 |

---

## 四、方案对比

### 方案 A：矩形框选 + 文本提取（推荐）

**交互**：
```
点击「选文」→ 右侧问答区出现透明选择层（与左侧共用同一把工具）
  → 在 AI 回答上拖矩形 → 松开
  → 根据矩形起止点提取范围内文字
  → 生成引用：「讲解师回答 · 问答摘录」+ 摘录文本
  → 出现在提问框上方引用区，可继续追问
```

**改动点**：
| 文件 | 改动 |
|---|---|
| `index.html` | `#chat-scroll` 内加 `<div id="chat-selection-layer">`（仅选文模式下可交互） |
| `src/main.js` | 监听工具状态切换选择层；拖动记录矩形；生成 text reference |
| 新增 `src/chat-selection.js` | `caretRangeFromPoint(起点/终点)` → `Range.cloneContents()` → 文本提取 |
| 引用格式 | `{ book: '讲解师回答', page: 当前页, text: 摘录, method: '问答摘录' }` |

**优点**：与左侧交互一致，平板拖框体验好
**缺点**：跨消息气泡需处理文本顺序；KaTeX 公式提取为源码文本（如 `\frac{1}{e^x}`）

### 方案 B：原生选择 + 引用按钮

**交互**：拖动选择文字（平板长按拖动）→ 浮出「引用这段」→ 点击加入引用

**优点**：实现简单，文本精确
**缺点**：平板长按选择不如拖框直观；与左侧交互不一致

---

## 五、推荐

**方案 A**。理由：
1. 与「选文」工具统一，用户不需要学两套操作
2. 平板触控场景下拖框比长按选字稳定
3. `caretRangeFromPoint` 在 Chromium/WebView 支持良好
