# 技术说明：左侧选文原理与右侧问答区无法照搬的原因

> 整理时间：2026-11-26
> 适用版本：讲课台 0.8.6
> 关联需求：[需求-右侧问答区框选.md](./需求-右侧问答区框选.md)

---

## 一、结论摘要

| 项 | 结论 |
|---|---|
| 左侧选文本质 | 利用 **PDF.js 的页面渲染能力**，把选区坐标映射到 PDF 页面上，重新渲染并裁剪成图片 |
| 右侧能否照搬 | **不能**。右侧是 DOM 文本，没有可重渲染的图像源，也没有浏览器区域截图 API |
| 右侧可行做法 | 矩形框选 + `caretRangeFromPoint` → `Range` **提取文字**，生成文本引用 |

## 二、左侧选文的实现原理

### 2.1 前提条件：左侧有"可渲染的页面对象"

左侧课本区由 PDF.js 渲染：每一页是一个 `PDFPageProxy`，可以通过 `page.getViewport()` 拿到尺寸，通过 `page.render()` 按任意缩放/偏移重绘到 canvas。

**这是左侧选文能做截图式引用的根本原因**——选区的坐标（0~1 归一化）可以直接映射回 PDF 页面坐标系，重新渲染出一张干净的裁剪图。

### 2.2 完整链路

```
① 点「选文」按钮
      ↓
② 工具切换到 select 模式
      ↓
③ 在 PDF 页面的 .ink-canvas 覆盖层上拖动
      ↓
④ setBounds() 记录归一化矩形（0~1），显示虚线框
      ↓
⑤ 点「添加截图」按钮
      ↓
⑥ quoteSelection() → capturePage()
      ↓
⑦ PDF.js 按选区重渲染 → canvas → JPEG data URL（超限自动缩小）
      ↓
⑧ onQuote() → state.references → 引用 chip
      ↓
⑨ 提问时 chatInput() 转成多模态 parts 发给模型
```

### 2.3 逐环节代码

**① 按钮**（`index.html` 第 47 行）
```html
<button type="button" data-tool="select" aria-pressed="false" title="拖动框选截图">选文</button>
```

**② 工具切换**（`src/reader.js` 第 49-53 行）
```js
byId('modes').addEventListener('click', (event) => {
  const button = event.target.closest('[data-tool]');
  if (!button) return;
  this.inkTools.select(button.dataset.tool);   // → setTool('select')
});
```

**③ 拖动**（`src/reader.js` 第 499-531 行）
- `pointerDown`：确认事件在 `.ink-canvas` 上、工具为 select → `setBounds(p, p)` 开始
- `pointerMove`：`setBounds(active.initial, point(event))` 持续更新矩形
- 坐标通过 `point()`（第 491-497 行）归一化为 0~1，与缩放无关

**④ 矩形记录**（`src/reader.js` 第 677-686 行）
```js
setBounds(a, b) {
  const bounds = { x: Math.min(a.x,b.x), y: Math.min(a.y,b.y),
                   w: Math.abs(a.x-b.x), h: Math.abs(a.y-b.y) };
  this.bounds = bounds;                    // 归一化坐标（相对画布 0~1）
  // 更新 #selection-rect 的 left/top/width/height（百分比）→ 显示虚线框
  byId('selection-note').textContent = '选区已标记，点「添加截图」加入本次提问。';
}
```

**⑤⑥ 确认与截图**（`src/reader.js` 第 887-904 行）
```js
async quoteSelection() {
  const bounds = this.bounds;
  if (!bounds || 宽 < 5px 或 高 < 5px) { 提示; return; }
  this.onQuote(await this.capturePage(this.page, bounds, '选文截图'));
}
```

**⑦ 渲染裁剪**（`src/reader.js` 第 835-881 行）
```js
const viewport = page.getViewport({ scale: 1 });
const width = viewport.width * bounds.w;
const height = viewport.height * bounds.h;
const scale = Math.min(4, 1700 / Math.max(width, height));
await page.render({
  canvasContext: context,
  viewport,
  transform: [scale, 0, 0, scale,
              -bounds.x * viewport.width * scale,
              -bounds.y * viewport.height * scale],
}).promise;
let image = canvas.toDataURL('image/jpeg', .86);
while (image.length > IMAGE_LIMIT && canvas.width > 1) {
  // 逐步缩小 80% 重新编码，直到 ≤ 310000 字符
}
```

关键点：
- `transform` 的负偏移把**选区左上角**对齐到画布原点 → 只输出选区内容
- `scale` 限制在 4 倍以内、最长边 1700px，避免图片过大
- 超过 `IMAGE_LIMIT`（`src/excerpts.js` 定义 310000）时循环缩小

**⑧ 引用生成**（`src/reader.js` 第 876 行）
```js
return { bookId, book, page, method, image, width, height };
```

**⑨ 发送**（`server/api.mjs` 的 `chatInput()`）
```js
...(ref.image ? [{ type: 'image_url', image_url: { url: ref.image } }] : []),
```

## 三、右侧问答区为什么不能照搬

右侧（`#chat-scroll` / `#messages`）是**渲染后的 DOM 文本**，与左侧有本质区别。

### 3.1 硬约束一：没有"可重渲染的页面对象"

左侧能截图，是因为 PDF.js 保留了页面原始数据（`PDFPageProxy`），可以随时按任意坐标重绘。

右侧的 AI 回答是 DOM 节点（`<li>` / `<p>` / KaTeX 渲染的公式），**没有对应的源数据对象**可供"按坐标重绘"。要得到图像只能对屏幕像素做截图。

### 3.2 硬约束二：浏览器没有 DOM 区域截图 API

| 尝试 | 结果 |
|---|---|
| `canvas.toDataURL()` | ❌ 只能截 canvas 自己，不能截 DOM |
| `navigator.mediaDevices.getDisplayMedia()` | ❌ 桌面端弹窗授权、WebView 不支持、用户拒绝则不可用 |
| `html2canvas` / `dom-to-image` | ❌ 第三方库；项目 CSP 为 `default-src 'self'`，且库体积大、对 KaTeX/WebView 兼容性差 |
| SVG `foreignObject` + canvas | ❌ 需要内联样式/字体，CSP 与跨域资源限制，公式渲染易失真 |

### 3.3 硬约束三：CSP 与安全策略

`index.html` 的 CSP：
```
default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; ...
```

- 不允许加载外部截图库
- 不允许 `data:` 之外的图片源（`img-src 'self' data: blob:`）
- 引入 html2canvas 需要打包进项目并修改 CSP，属于高风险改动

### 3.4 结论

**右侧选文不能走"截图"路线，只能走"文本提取"路线。**

## 四、右侧可行的替代路径（文本提取）

### 4.1 原理

```
用户在右侧拖矩形
    ↓
矩形起点/终点 → document.caretRangeFromPoint(x, y) → 文本节点 + 偏移
    ↓
new Range(startNode, startOffset, endNode, endOffset)
    ↓
range.cloneContents() 或 range.toString() → 选中的文字
    ↓
生成文本引用：{ book: '讲解师回答', page: 当前页, text: 摘录, method: '问答摘录' }
```

`caretRangeFromPoint` 在 Chromium / Android WebView / HarmonyOS ArkWeb 中均支持。

### 4.2 与左侧的差异

| 环节 | 左侧 | 右侧（文本提取） |
|---|---|---|
| 选区记录 | `.ink-canvas` 上的矩形 | 新的透明选择层上的矩形 |
| 内容来源 | PDF 页面重渲染 | DOM 文本节点 |
| 引用类型 | `image` + `width/height` | `text`（24000 字符上限） |
| 显示 | 缩略图 chip | 文字 chip |
| 模型接收 | 多模态图片 parts | JSON 文本资料 |

### 4.3 限制

1. **公式**：KaTeX 渲染的公式提取到的是源码文本（如 `\frac{1}{e^x}`），不是图像，但模型能理解
2. **跨气泡**：框选跨多个消息时，需要按 DOM 顺序拼接文本（`Range.cloneContents()` 天然保持顺序）
3. **图片内容**：若回答里含图片，文本提取拿不到图片本身
4. **无视觉模型依赖**：文本引用走纯文本通道，NK-GeniOS 可直接使用，**不需要视觉 Key**

## 六、对实施方案的启示

1. 右侧选择层**不需要 canvas**，用普通 `<div>` + pointer 事件即可（参考左侧 `setBounds` 的矩形逻辑，可复用）
2. 文本提取用 `caretRangeFromPoint`，不需要引入任何第三方库
3. 引用类型用 `text`，服务端 `chatInput()` 已有文本分支（`{ text: ref.text }`），**服务端零改动**
4. 文本引用不依赖视觉模型，Android 端也能用
